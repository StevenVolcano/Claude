# TERMINUS — Android app module

The Android UI for the game described in [`../GAME_DESIGN.md`](../GAME_DESIGN.md),
structured per [`../ARCHITECTURE.md`](../ARCHITECTURE.md) §1.2. Everything is
Jetpack Compose in a single activity; the map is osmdroid wrapped in `AndroidView`.

## Building

This module needs the **Android SDK** and access to Google's Maven repository
(neither is available in the `:core`-only CI environment):

1. Install Android Studio or a command-line SDK (API 35 / build tools for AGP 8.7).
2. Make the SDK discoverable — either export `ANDROID_HOME`, or create
   `local.properties` at the repo root with `sdk.dir=/path/to/Android/sdk`.
3. `settings.gradle.kts` then **auto-includes `:app`** (it is skipped when no SDK
   is detected, so `./gradlew :core:test` keeps working everywhere).
4. Build: `./gradlew :app:assembleDebug` → `app/build/outputs/apk/debug/`.

Toolchain notes: Kotlin 2.0.21 + the Compose compiler plugin come from the root
`build.gradle.kts` plugins block; AGP 8.7.3 is versioned *in this module's*
`build.gradle.kts` on purpose (Google-Maven-only artifact; see the comment there).

## Engine wiring (Phase 3, done)

All screens, view models, storage, the foreground service, and the map bind to a
single facade: **`di/GameSessionFactory.kt`** (`GameSession` interface). That file
(plus `di/ActiveSessionHolder.kt`) is the *only* place allowed to import
`io.terminus.core.engine` and `io.terminus.core.ai`. The factory builds the real
thing:

- `engine.GameRunner` over the `CityFile`, with `RealTimeSource` (GPS, 1:1) or a
  pausable `ScaledTimeSource` (sim) and the player roster from
  `GameSessionFactory.buildPlayers` (engine ids `ai-1`…`ai-n`, app display names);
- one `engine.RoundAwareAiBrain` per AI opponent (`engine.aiBrainsFor`), which
  rebuilds the W7 hider/seeker brain per round as roles rotate;
- an "auto" RNG seed is stamped with the epoch millis at session creation so the
  whole match is reproducible from the recorded config;
- `GameViewModel.endMatchAndRecord` persists `GameSession.buildMatchRecord` — the
  runner-produced per-round `RoundRecord`s plus §7 totals/tiebreaks;
- sim-mode autosave saves `GameSession.replayLog()` (the command log) every 30 s;
  Home's *Resume* rebuilds a dead session by command-log replay
  (`core`'s `engine.Replay.rebuildRunner`); GPS mode is not resumable.

## OpenStreetMap tile policy

Tiles come from the standard OSM Mapnik servers. Per the
[OSM tile usage policy](https://operations.osmfoundation.org/policies/tiles/):

- a project-identifying user agent is set once in `map/MapSetup.kt`
  (`terminus-game`) — keep it meaningful if you fork;
- tiles are disk-cached under `cacheDir/osmdroid/tiles`;
- the map degrades gracefully offline: overlays (boundary, routes, stations,
  tokens) render over a blank grid, and the game stays fully playable.

Do not ship heavy traffic against the public servers; switch the tile source in
`MapSetup` if this ever goes beyond personal use.

## Assets

`src/main/assets/cities/` holds the two bundled demo cities
(`demoville`, `port-saltmarsh`) generated by `core`'s `DemoCities`; they are copied
to `filesDir/cities/` on first run by `AppStorage.copyBundledCitiesIfNeeded()`.
Do not edit the `.city.json.gz` files by hand — regenerate via the core generator.

## Manual test script

1. **Home** → *Cities*: both demo cities listed with station/route counts.
2. *Import GTFS…*: pick any GTFS zip → boundary draw step → report screen →
   imported city appears in the list (delete it afterwards to clean up).
3. **Home** → *New game*: pick Demoville; try each boundary type (polygon
   tap/undo/clear, circle center + radius slider); toggle a mode off and verify
   the "at least one route" validation; switch Couch mode and verify default
   durations change to 45/10; set 2 AIs, personality mode *Manual*, pick distinct
   personalities; save a preset, change options, load the preset back.
4. *Start game*: map shows boundary, colored lines, stations, tokens at the start
   station. Top bar ticks; in sim mode Pause/Resume works and the time-scale label
   matches setup.
5. Tabs: *Questions* (locked during hiding phase; category list with cooldown
   labels after), *Cards* ("hand empty" as hider; "hider-only" note as seeker),
   *Log* (phase-change entries appear).
6. Quit → confirm → Home. *History* shows recorded matches after *End match* from
   the end screen.
7. GPS mode (on device): grant location permission; the persistent notification
   shows phase + clock and survives backgrounding.

Question/card flows (answers, compensation draws, captures, scores) run against
the real `GameRunner`; the deterministic AI-vs-AI path is covered by
`core/src/test/kotlin/io/terminus/core/integration/` (smoke + replay tests).
